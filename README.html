Codex Statebar

为 Codex CLI 提供配额、上下文、模型、推理强度、Git、活动、预测和多主题状态栏。

⤷ codex-statebar ⎇ main●
⚙ effort:high

数据直接来自本地 $CODEX_HOME/sessions 与 $CODEX_HOME/archived_sessions；不会读取 auth.json，不会上传 session 内容。独立运行时默认只选择当前目录的顶层 Codex CLI 会话，不会混入同目录的 Codex Desktop / VS Code 会话。

视觉配置优先读取 ~/.codex/codex-statebar.json；若没有 Codex 专属覆盖，则继承现有 ~/.claude/claude-statusbar.json，使 cs 与 cxs 默认保持同一套样式、主题、颜色和密度。

安装

curl -fsSL https://raw.githubusercontent.com/leeguooooo/codex-statebar/main/install.sh | sh
cxs doctor

一键安装会校验 SHA-256，安装 cxs、补丁版 codex-cxs 与用户级 codex 启动器，并通过 cxs --setup 接入状态栏。已有的 ~/.local/bin/codex 会先备份；ChatGPT App 内置二进制不会被修改。

启动器会比较 PATH 中的官方 Codex 和补丁版：补丁版版本相同或更新时运行 codex-cxs；官方版更新时改为运行官方版，并提示嵌入式状态栏暂时停用。这样官方更新不会被旧补丁版静默遮住。cxs upgrade 会一起校验并更新 cxs 与 codex-cxs。

发布物由 GitHub Actions 为 macOS / Linux 构建为独立二进制；用户端不需要 Python 或 Rust。若不想安装用户级启动器，设置 CODEX_STATEBAR_INSTALL_CODEX_DEFAULT=0。

macOS / Linux 版首次启动时将运行时展开到 ~/.local/lib/codex-statebar/<内容校验值>/，后续启动复用该目录，不再为每次刷新创建 _MEI…。文件锁保护并发初始化，中断后自动重建不完整目录。可用 CODEX_STATEBAR_RUNTIME_DIR 指定存放位置。旧运行时保留供现有会话使用；升级更新安装入口。

Codex TUI 状态栏

稳定版 Codex 的 [tui].status_line 只接受内置项目 ID。cxs --setup 写入兼容的原生状态栏；富状态栏可用 cxs 或 cxs watch 查看。
cxs --setup

配置包含模型、目录、Git 分支、上下文余量、5 小时与每周限额、Fast 状态。重启 Codex CLI 后生效。

需要试验性的嵌入式富状态栏时，可运行 ./scripts/build-patched-codex.sh，再显式启动 ./dist/codex-cxs。补丁固定对应 rust-v0.145.0；官方 Codex 版本更高时，默认启动器不会自动降级。

上游扩展点进展见 openai/codex#17827。

新建 Codex CLI 后，需要至少发送一条消息，Codex 才会创建可读取的 rollout。若尚未发送消息，cxs 会提示先完成首轮交互；它不会改用同目录的 Desktop 会话。

上下文与缓存计算

上下文用量读取最近一次 token_count：total_tokens / model_context_window。cached_input_tokens 虽可减少计费，但仍占用模型上下文，因此包含在已用 token 中；另行计算 billable input 时才从 input tokens 中扣除。

cache 3m24s 是 Claude prompt cache 的剩余 TTL：使用最近 assistant turn 的时间戳，并从写入桶自动识别 5 分钟或 1 小时 TTL。Codex rollout 目前只提供 cached token 数量，不提供缓存创建时间或 TTL，所以 Codex 内不会伪造 cache COLD 或倒计时。
