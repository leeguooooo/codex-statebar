Codex Statebar

English · 简体中文

Weekly quota, context, model, reasoning effort, Git, activity, projections and a themeable status bar for the Codex CLI.

What it shows

cxs --style aurora draws gradient progress bars and shows the model's context usage as its own percentage. The classic, capsule and hairline styles are kept. Every style reflows to the terminal width, and an overlong field is truncated by display width, so CJK text lines up.

Data comes straight from the local $CODEX_HOME/sessions and $CODEX_HOME/archived_sessions. It never reads auth.json and never uploads session content. Run standalone, it picks only top-level Codex CLI sessions in the current directory, never Codex Desktop or VS Code sessions from the same directory.

Visual settings come from ~/.codex/codex-statebar.json first. Without a Codex-specific override they inherit ~/.claude/claude-statusbar.json, so cs and cxs share one style, theme, palette and density by default.

Install

curl -fsSL https://raw.githubusercontent.com/leeguooooo/codex-statebar/main/install.sh | sh
cxs doctor

The one-liner verifies SHA-256 checksums, installs cxs, the patched codex-cxs and a user-level codex launcher, then wires up the status bar with cxs --setup. An existing ~/.local/bin/codex is backed up first; the binary bundled with the ChatGPT app is never modified.

The launcher compares the official Codex on your PATH with the patched build. When the patched build is the same version or newer, it runs codex-cxs. When the official Codex is newer, it runs the official one with its native status line. An official update is never silently hidden behind an older patched build. cxs upgrade verifies and updates cxs and codex-cxs together.

GitHub Actions builds the releases as standalone binaries for macOS and Linux; users need neither Python nor Rust. To skip the user-level launcher, set CODEX_STATEBAR_INSTALL_CODEX_DEFAULT=0.

On macOS and Linux the runtime unpacks once to ~/.local/lib/codex-statebar/<content-hash>/, and later launches reuse it instead of creating a _MEI… directory on every refresh. A file lock guards concurrent first runs, and an incomplete directory left by an interrupted run is rebuilt automatically. Set CODEX_STATEBAR_RUNTIME_DIR to choose the location. Shared locks protect runtimes still in use; the current version and one idle fallback are kept, and other exited versions and interrupted unpack directories are reclaimed. Older versions without a lock marker are left for manual review. Upgrades update the entry point.

Version probing skips cmux's forwarding shim. If another wrapper routes back into cxs, a re-entrancy guard rejects the probe immediately, so no recursive process chain can form.

Live panel for one session

The 5-hour window appears only when Codex reports one (Pro does; the 100 and 200 plans do not), with its natural reset countdown. With both windows shown, Aurora drops the context mini bar and keeps the percentage.

cxs watch --session <thread-id> --style aurora --theme nord --interval 1

Without --session it follows the most recent top-level CLI session in the current directory. With a session or path given, a missing one is shown as missing; it never switches to another session. Ctrl+C exits and restores the previous screen and cursor. Redirected to a file it writes plain text; --no-color turns colors off.

Context and quota each come from their latest valid record. A quota past its reset time shows as unknown until new data arrives instead of a fake zero, and an empty token event never wipes the previous context data.

Codex TUI status bar

When the codex launcher picks a compatible patched build, it turns on the embedded rich status bar with your chosen style; there is no need to run watch in another terminal. When the official Codex is newer than the patched build, it switches to the official one and its native status line.
cxs --setup

The native fallback shows model, directory, Git branch, context remaining, weekly limit and Fast state. The native settings stay in config.toml; the external command is passed only to the patched process by the launcher, so switching to the official Codex later leaves no incompatible configuration behind. Restart the Codex CLI after installing or upgrading.

The current patch targets rust-v0.164.0. After installing, just run codex: the status bar takes its own measured area of up to 6 lines under the input box, and reflows to the actual available width when the window narrows. If the command times out, fails or prints too much, the native status line is shown instead. cxs doctor checks which version was picked and how it is wired.

In a new Codex CLI session, send at least one message before Codex creates a readable rollout. Until then cxs asks you to finish the first turn; it never falls back to a Desktop session in the same directory.

New looks, worktrees, OCS and updates

When a new set of looks ships, the status bar shows New looks · cxs theme. Run cxs theme and pick Aurora block, Aurora thin, Ring or Classic with the arrow keys and Enter; cancelling keeps your current style, and the hint disappears once you have looked. Set the hint language with lang zh or lang en; it follows the system by default. You can also set bar_glyph thin directly. For narrow terminals, narrow_layout stack wraps fields onto more lines and narrow_layout drop hides trailing fields. cxs themes still lists the palettes.



The worktree line shows the checkout name, the main repository and the number of live checkouts, excluding leftover records of deleted checkouts. The main checkout shows the count too. Adjust it with cxs config set worktree_glyph ⑂ and cxs config set color_worktree "#bd93f9".

With OCS installed, a separate line shows the current Codex session's address, unread messages and LAN state. It only runs ocs whoami --json, ocs inbox --json and ocs lan status --json, matches the full thread ID and caches for 30 seconds. When OCS is not installed or does not know the current session, the line is hidden; it never borrows another session's identity.

Every 6 hours a background check looks for a new GitHub Release, verifies its SHA-256 and upgrades. cxs config set auto_upgrade false turns off automatic installs but keeps the version check and hint; CODEX_STATEBAR_NO_UPDATE=1 turns off the check. You can also run cxs upgrade --check or cxs upgrade. If a new release also changes the native Codex version, the background check only shows a hint; exit Codex and run cxs upgrade, so the tool host a running session uses is never replaced. On Windows a running EXE is locked by the system, so it only suggests reinstalling.

Resource retention

watch and the daemon clean rebuildable caches every 30 minutes; cxs gc runs it immediately. Idle session caches are kept for 24 hours, with at most 256 idle directories. Git, balance and OCS caches are kept for 30 days, at most 1024 files each. State written in the last hour is never evicted, so running windows can rebuild their caches.

Each daemon log is capped at 1 MiB with a single rotated file. Newly generated system services add no separate stdout/stderr files. Maintenance touches only cxs's own caches: never Codex's sessions, archived_sessions or config files, and it does not follow symlinks inside the cache.

How context and cache are computed

Context usage reads the latest token_count: total_tokens / model_context_window. cached_input_tokens lowers the bill but still occupies the model's context, so it counts as used; it is subtracted from input tokens only when computing billable input.

cache 3m24s is the remaining TTL of Claude's prompt cache: it uses the latest assistant turn's timestamp and detects a 5-minute or 1-hour TTL from the write bucket. Codex rollouts currently report only the cached token count, with no cache creation time or TTL, so Codex never shows a fake cache COLD or countdown.

Official reset announcements appear at the end of the first line, distinguishing completed resets, scheduled announcements awaiting execution, and AI forecasts. They do not confirm credit in your own account. Announced times are approximate: once your own quota windows restart early, the line switches to a highlighted ✓ Quota reset · seen … and stops showing the countdown. Reset messages follow the system language in Simplified Chinese, Traditional Chinese, English, Japanese or Korean. Use cxs config set lang auto, or select zh, zh-TW, en, ja or ko. Disable the line and background refresh with cxs config set show_resets false. The Codex Resets API is refreshed in the background every five minutes; rendering never waits for network access.
